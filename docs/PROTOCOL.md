# 子機 ↔ 親機 プロトコル v2

XBee 3 (Zigbee 3.0) 上のテキストプロトコル。1メッセージ = ASCII 1行(`\n` 終端)。

- 子機 XBee: AP=0(透過モード)、DH/DL=0(宛先コーディネータ)、BD=9600
- 親機 XBee: AP=1(API モード、エスケープなし)、CE=1
- ノード番号は親機が送信元 64bit アドレス(MAC)から決める。子機は番号を持たない(全子機同一ファーム)

## 要求(親機 → 子機、ユニキャスト)

```
REQ,<seq>\n
```

- `seq`: 0〜65535 の10進。親機が要求ごとに増やす(全ノード共通カウンタ)
- 旧子機(v1)は `indexOf("REQ")` で反応するので、この形式でも従来どおり応答する

## 応答(子機 → 親機)

### v2

```
D2,<seq>,<n_ok>,<n_try>,<med_us>,<min_us>,<max_us>,<uptime_s>,<fw>\n
```

| フィールド | 内容 |
|---|---|
| `seq` | 要求の `seq` をそのまま返す。`seq` なしの `REQ` には `-1` |
| `n_ok` / `n_try` | バースト測定の有効回数 / 試行回数 |
| `med_us` | 有効エコー時間(往復、µs)の中央値。`n_ok=0` のとき `-1` |
| `min_us` / `max_us` | 有効エコー時間の最小・最大。`n_ok=0` のとき `-1` |
| `uptime_s` | 子機の起動からの秒数(再起動の検出用) |
| `fw` | ファームウェア版数(例 `2.0.0`) |

距離の換算は親機・後処理で行う。シートの `Dist20_cm` は 20℃(343.4 m/s)固定の名目値:

```
dist_cm = med_us * 0.034340 / 2
```

温度補正は後処理で `c = 331.3 + 0.606 * T` を使って再計算する。

### v1(旧子機、受信のみ互換)

```
ID[n],<dist_cm>,<temp>,<hum>,<pres>\n     (欠測は -999.0)
ID[n],NoData\n
```

親機は `status=OK_V1` として距離だけを記録する。`seq` がないので遅延応答の判定はできない。

## 親機の地点のセンサ(USB シリアル)

親機に USB でつないだ ESP32(子機と同じファーム、v2.1.0 以降)とも同じ `REQ` / `D2` でやりとりする。XBee は通らない。

- 115200 bps、`\n` 区切り。親機 → ESP32 は `REQ,<seq>\n`、ESP32 は `D2,...\n` を USB に返す
- USB には子機ファームのデバッグ出力(`ping ...` など)も流れる。親機は `D2,` で始まる行だけを読み、`seq` が一致したものを採用する
- ノード番号は親機の設定 `[local] node` で決める。記録の `mac` は `LOCAL`、`tx_status` は空
- XBee が使えないときも、このセンサは測る

## 親機側の判定

1要求につき、次のいずれかの status を1行記録する。

| status | 条件 |
|---|---|
| `OK` | v2 応答、`seq` 一致、`n_ok > 0` |
| `NO_ECHO` | v2 応答、`seq` 一致、`n_ok = 0`(子機は生きているがエコーなし) |
| `OK_V1` | v1 応答で距離あり |
| `NO_DATA` | v1 応答で `NoData` または距離 `-999` |
| `TX_FAIL` | XBee の Transmit Status が成功以外(`tx_status` にコード) |
| `TIMEOUT` | 配送は成功(または不明)だが応答期限内に返事なし |
| `BAD_REPLY` | 応答はあるが解析できない(`raw` に原文) |
| `RADIO_ERR` | 親機の XBee 自体が使えない |
| `PORT_ERR` | 親機の地点のセンサ(USB)が開けない・読み書きできない(`raw` に理由) |

`seq` が一致しない v2 応答(前回の遅延応答など)は捨ててログにだけ残す。
